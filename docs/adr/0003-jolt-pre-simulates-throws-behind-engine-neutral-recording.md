# Throws are pre-simulated by Jolt behind an engine-neutral recording

Jolt Physics, through jolt-jni (≥ 6.2.0), pre-simulates every Throw on a single physics worker. Nothing engine-specific crosses the module boundary: the worker takes release conditions and returns a recording made of our own types. The recording holds each Die's position and orientation per sample, the moment every Die is at rest, and contact events (time, the Dice involved, impulse). We chose Jolt for three reasons. Its convex radius rounds a hull's edges without enlarging it, so each Die Kind is one rounded `ConvexHullShape` built from its sharp vertices. It has sleep detection we can poll. And it is a real JPMS module with a passing JDK 27 CI job, which `jlink` needs. Determinism, Jolt's other headline strength, plays no part, because ADR-0001 replays recordings instead of re-simulating. We locked the engine without a spike. Rest timing, settle speed and native packaging are tuning and packaging work under any engine, and the recording seam keeps a later swap contained.

## Considered Options

- **Bullet via Libbulletjme.** It is the named fallback if Jolt hits a blocker during the build. It has the same maintainer, native packaging and JDK 27 CI. It lost because its hull margin *enlarges* the shape, so vertices must be offset inward by hand, and because it has no `module-info`.
- **ode4j (pure Java).** No natives was its only advantage, and that is weak: LWJGL natives ship anyway. It is dormant, has no rounding primitive, and keeps a process-global RNG.
- **PhysX via physx-jni.** It cannot round an arbitrary hull (`PxConvexCoreGeometry` has no hull core), and its CI runs only on JDK 17.

## Consequences

- **Centimetres.** The physics world and the recording use centimetres, with gravity ≈ 981 cm/s². Jolt's metre-scale defaults (0.02 contact distance and slop, 0.05 convex radius) then read as dice-scale tolerances without retuning each one. The renderer's world unit is the centimetre too.
- **One solid per Die Kind.** Physics and rendering share one procedural definition: vertices, face table and edge radius. Physics uses the sharp vertices with the edge radius as the convex radius, and the renderer builds its rounded mesh from the same definition. The face the renderer shows as up is therefore the face physics settled on, which the numbering rotation of ADR-0001 depends on. The percentile d10 reuses the d10 solid.
- **A separate release generator.** Release conditions (start pose, velocities, per-retry variation) come from a second injected `RandomGenerator`, never the one that chooses Face Values. A Throw that retries therefore never shifts later Face Values, and a fixed-seed test of a roll sequence stays reproducible however physics behaves.
- **Four endings.** A pre-simulation ends in one of four ways. *At rest* means every body sleeps, polled on the worker after each step and never through Jolt's multi-threaded activation callbacks. *Cocked* means some Die's best face normal (or, for the d4, its best vertex) lies outside a tolerance from vertical. *Escaped* means a Die left the tray volume. *Timed out* means the simulated time exceeded a cap. Every ending except at rest re-simulates the Throw and counts toward ADR-0001's retry cap.
- **Fresh per attempt.** Each attempt builds a new physics system with a single-threaded job system and frees its native objects explicitly at the end. jolt-jni's cleaner thread is not started, so no native state outlives an attempt.
- **Native packaging.** The app ships the default native flavours (`Windows64`, `Linux64`, `MacOSX64`, `MacOSX_ARM64`), never `_avx2` or `_fma`, in `ReleaseSp`. `DebugSp` is available through a dev-only Maven profile. JSnapLoader is not used. jolt-jni and LWJGL natives are laid into the `jlink`/`jpackage` image at build time and loaded with `System.load` by one loader of ours, so a read-only install location never needs a runtime extraction.
- **Native access.** `--enable-native-access` is granted to exactly the modules that need it (jolt-jni, LWJGL, and our module that calls `System.load`), never `ALL-UNNAMED`. Dev and test runs use `--illegal-native-access=deny`, so a missing grant fails now rather than after a JDK upgrade.
- **Eager start-up.** Jolt's process-wide setup (native load, allocator, factory, type registration) runs once at app start on the physics worker. If it fails, the app fails fast with a message naming the platform and the library, as ADR-0002 does for GL 3.3. Jolt's trace output goes to the app log.
